## For recruiters and non-technical reviewers

Pro-Code demonstrates how a large AI-native engineering portfolio behaves as **one governed operating system rather than hundreds of disconnected repositories**.

A developer, reviewer, or AI agent can enter through any linked core repository and recover:

- the system's purpose and identity;
- the relevant memory and prior decisions;
- the authority boundary for acting;
- the correct tool and execution plane;
- the best-fit language and runtime;
- the verification standard;
- the exact completion or blocker receipt.

The result is not decorative multi-language code. It is an engineering nervous system that selects the right technology, acts within authority, repairs failures before reporting them, and preserves what it learned.

## For senior engineers

### Operating protocol

```text
MEMORY → TOOL → CURE → INNOVATE → RESPOND
```

Expanded engineering lifecycle:

```text
DISCOVER
→ recover canonical memory and topology
→ bind purpose, identity, constraints, and authority
→ select the existing execution plane
→ select language/runtime through Tower contracts
→ implement the smallest coherent change
→ test and inspect receipts
→ repair or reroute failures
→ add one measurable resilience or integration gain
→ verify target state
→ persist artifacts, decisions, and evidence
→ report only the completed result or exact exhausted blocker
```

### Non-negotiable rules

1. **Memory first.** Do not design from an empty context when canonical memory exists.
2. **Reuse before invention.** Discover the existing repository, connector, schema, component, and execution plane.
3. **No novelty refactors.** Preserve working code unless measurable value requires change.
4. **Polyglot by boundary, not theater.** A language earns adoption through safety, performance, hardware fit, ecosystem fit, formal proof, or interoperability.
5. **Cure before report.** Read-only diagnosis is not completion while a safe authorized repair remains available.
6. **Receipts over claims.** A plan, patch, or successful command is not complete without target-state verification and persistence.
7. **Every doorway exposes the mesh.** README, manifest, and agent contracts must link back to the nervous-system topology.

## Polyglot execution boundary

The Tower of Babel owns technology placement. Pro-Code consumes those decisions.

| Boundary | Preferred owner |
|---|---|
| Browser, MCP, JSON/RPC, edge interfaces | TypeScript |
| Orchestration, AI, document intelligence, automation | Python |
| Canonical state, constraints, vectors, audit queries | SQL |
| Evidence integrity, native safety, cryptographic or concurrent governors | Rust |
| Network daemons, telemetry, operational services | Go |
| Native ABI, firmware, kernels, constrained systems | C/C++/Zig as justified |
| Formal invariants | Lean, Coq, TLA+, Alloy, or another Tower-governed proof floor |

See [The Tower of Babel](https://github.com/GlacierEQ/the-tower-of-babel) for canonical placement, build gates, interfaces, and evidence levels.
