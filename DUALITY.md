## Why the pair exists

- **`Pro_Code`** (underscore, case-sensitive display name): private GENIUS engineering doctrine, Operator-directed standards, research, playbooks, context and architecture philosophy.
- **`pro-code`** (hyphen, this repository): public implementation, compiler-backed coding, Node services, React/TypeScript UI, worker routing, native verification, artifacts and measurable behavior.

Each side must **reason, build, test and learn**. Primary responsibility is not a prohibition on thinking or executing in the other strand.

## Boot and action contract

1. Read the user's latest objective and corrections. Retrieve current doctrine from `Pro_Code` **if authorized**, and read this repository's `AGENTS.md`.
2. Study the current code, owning modules, tests, dependency graph and relevant companion sources. Preserve all working behavior.
3. Choose the strongest coherent engineering improvement within scope; use existing mechanisms where available, not a second redundant framework.
4. Implement the change in native source, test, repair, measure impact and verify GitHub/provider receipts.
5. Record exact revisions and verified capability deltas. Send source-linked discoveries back to the companion doctrine as appropriate.
6. Continue independent work when one link or provider is unavailable. The private source being inaccessible must not be impersonated or inferred.

### Identity reconciliation

Historical docs sometimes call this repository the "brains" and `Pro_Code` the "brawn"; more recent `.helix/strand.json` files define doctrine and runtime strands. These aren't mutually exclusive human capabilities. **Source ownership is determined by the actual file, code and demonstrated behavior, not the metaphor.** Do not delete historical declarations or invert their meaning when updating a specialized source.
